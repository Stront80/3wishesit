# «Три желания» — GitHub Pages

Статическая версия лендинга для публикации на GitHub Pages с пользовательским доменом `3itwishes.site`.

## 1. Опубликовать сайт

1. Создайте репозиторий GitHub, например `tri-zhelaniya-site`.
2. Загрузите содержимое этой папки в корень ветки `main`. В корне должны находиться `index.html`, `styles.css`, `app.js`, `privacy.html`, `CNAME` и остальные файлы.
3. Откройте **Settings → Pages**.
4. В **Build and deployment** выберите **Deploy from a branch**, ветку `main`, папку `/ (root)`, нажмите **Save**.
5. В **Custom domain** укажите `3itwishes.site` (если домен уже указан из файла `CNAME`, проверьте, что GitHub его распознал).
6. После обновления DNS и выпуска сертификата включите **Enforce HTTPS**.

## 2. DNS для `3itwishes.site`

У DNS-провайдера создайте четыре A-записи:

| Type | Host / Name | Value / IPv4 |
|---|---|---|
| A | `@` | `185.199.108.153` |
| A | `@` | `185.199.109.153` |
| A | `@` | `185.199.110.153` |
| A | `@` | `185.199.111.153` |

Рекомендуемые IPv6-записи (AAAA), если DNS-провайдер поддерживает IPv6:

| Type | Host / Name | Value / IPv6 |
|---|---|---|
| AAAA | `@` | `2606:50c0:8000::153` |
| AAAA | `@` | `2606:50c0:8001::153` |
| AAAA | `@` | `2606:50c0:8002::153` |
| AAAA | `@` | `2606:50c0:8003::153` |

Для адреса `www.3itwishes.site` добавьте CNAME:

| Type | Host / Name | Target / Value |
|---|---|---|
| CNAME | `www` | `<ВАШ_GITHUB_USERNAME>.github.io` |

Замените `<ВАШ_GITHUB_USERNAME>` на имя аккаунта или организации GitHub, где опубликован сайт. Не добавляйте имя репозитория в значение CNAME. Если провайдер не поддерживает IPv6 или вы не хотите его настраивать, AAAA-записи можно не добавлять. Удалите конфликтующие A/AAAA/CNAME записи для `@` и `www`, если они указывают на другой хостинг. Не создавайте wildcard-запись `*`.

Сначала добавьте custom domain в настройках GitHub Pages, затем настраивайте DNS. Изменения DNS могут распространяться до 24 часов. Официальная документация: https://docs.github.com/en/pages/configuring-a-custom-domain-for-your-github-pages-site/managing-a-custom-domain-for-your-github-pages-site

## 3. Проверка DNS

После сохранения записей выполните в терминале:

```bash
dig 3itwishes.site A +short
dig 3itwishes.site AAAA +short
dig www.3itwishes.site CNAME +short
```

В ответе A должны быть четыре IPv4-адреса GitHub Pages. CNAME для `www` должен указывать на `<ВАШ_GITHUB_USERNAME>.github.io`.

## 4. Важное ограничение формы

GitHub Pages обслуживает только статические файлы: он не запускает Node.js и не может безопасно отправлять SMTP-письма с сервера. Текущая форма проверяет поля и открывает почтовое приложение посетителя с подготовленным письмом на `mailbox@familypost.ru`; посетитель должен нажать «Отправить». Это не автоматическая отправка. Для автоматического получения заявок используйте серверную версию на VPS или отдельный backend/form service. SMTP-пароль нельзя помещать в HTML, JavaScript или публичный репозиторий.

## 5. Перед запуском

- `privacy.html` содержит шаблонные юридические пометки. Заполните сведения об операторе, сроки хранения и порядок обработки/удаления данных; проверьте текст до сбора заявок.
- Проверьте ссылки контактов, мобильную версию и тестовую заявку.
- Если сайт использовался ранее на другом домене, убедитесь, что DNS-записи не конфликтуют.
